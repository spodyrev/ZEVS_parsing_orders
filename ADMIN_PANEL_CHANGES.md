## 🎯 Система прав доступа

### Уровень 1: Пользователь
```
is_admin = 0
is_superadmin = 0
```
**Может:**
- ✅ Авторизоваться в системе
- ✅ Просматривать заказы
- ✅ Использовать Telegram бота

**Не может:**
- ❌ Входить в админ-панель

### Уровень 2: Администратор
```
is_admin = 1
is_superadmin = 0
```
**Может:**
- ✅ Все права пользователя
- ✅ Входить в админ-панель
- ✅ Добавлять обычных пользователей
- ✅ Деактивировать/удалять пользователей

**Не может:**
- ❌ Назначать администраторов
- ❌ Назначать суперадминистраторов

### Уровень 3: Суперадминистратор
```
is_admin = 1
is_superadmin = 1
```
**Может:**
- ✅ Все права администратора
- ✅ Назначать администраторов
- ✅ Назначать суперадминистраторов
- ✅ Полный контроль над системой

## 🔧 Технические детали

### Миграция базы данных

**SQL:**
```sql
ALTER TABLE users 
ADD COLUMN is_superadmin INTEGER DEFAULT 0 NOT NULL;

UPDATE users 
SET is_superadmin = 1 
WHERE is_admin = 1;
```

**Безопасность:**
- Можно запускать несколько раз
- Автоматически преобразует существующих админов
- Не удаляет данные

### Проверка прав в коде

**В auth.py:**
```python
async def get_current_superadmin_user(
    current_user: User = Depends(get_current_user)
) -> User:
    if not current_user.is_superadmin:
        raise HTTPException(403, "Требуются права суперадминистратора")
    return current_user
```

**В app.py:**
```python
@app.post("/api/admin/users")
async def create_user(
    user_data: UserCreate,
    admin: User = Depends(get_current_admin_user)
):
    # Проверка прав
    if (user_data.is_admin or user_data.is_superadmin) and not admin.is_superadmin:
        raise HTTPException(403, "Только суперадмины...")
```

## 🔐 Безопасность

### Реализованные меры защиты

1. **Проверка прав на backend**
   - Обычные админы не могут назначать других админов
   - Невозможно обойти через API

2. **Проверка прав на frontend**
   - Checkbox "Суперадминистратор" скрыт для обычных админов
   - Условный рендеринг в Jinja2

3. **Невозможно удалить себя**
   - Защита от случайного удаления своего аккаунта

4. **Деактивация вместо удаления**
   - Рекомендуется сначала деактивировать пользователя
