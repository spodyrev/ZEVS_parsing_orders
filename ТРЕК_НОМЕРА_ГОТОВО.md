## ⚙️ Логика получения трек-номеров:

### Когда получаются:
- ✅ Статус = **"shipped"** (В пути)
- ✅ Статус = **"delivered"** (Доставлено)

### Когда НЕ получаются:
- ❌ Статус = **"created"** (Создан)
- ❌ Статус = **"paid"** (Оплачен, ждет отправки)
- ❌ Статус = **"cancelled"** (Отменен)

**Причина:** Taobao API возвращает трек-номера только после отправки товара.

## ❓ FAQ:

### Q: Почему у некоторых заказов нет трек-номера?
**A:** Товар ещё не отправлен (статус "paid" или "created"). Трек-номер появится после отправки.

### Q: Как часто обновляются трек-номера?
**A:** Автоматически каждые 2 часа вместе с синхронизацией, или вручную по кнопке.

### Q: Сколько заказов обрабатывается за раз?
**A:** Максимум 10 заказов без трек-номеров за одну синхронизацию (чтобы не перегружать API).

### Q: Что если API вернет ошибку?
**A:** Система продолжит работать, ошибка будет в логах. При следующей синхронизации попробует снова.

## 📝 Технические детали (для справки):

### Изменения в коде:

1. **`backend/scheduler.py`**:
   - Добавлен метод `_update_tracking_numbers()`
   - Вызывается после каждой синхронизации
   - Использует `client.get_order_details()` → `TaobaoParser.parse_tracking_from_detail()`

2. **Логика**:
   ```python
   # Находим заказы без трек-номера (только shipped/delivered)
   orders = db.query(Order).filter(
       Order.tracking_number.is_(None),
       Order.status.in_(["shipped", "delivered"])
   ).limit(10).all()
   
   # Для каждого заказа:
   detail_data = client.get_order_details(order.order_id)
   tracking_number = TaobaoParser.parse_tracking_from_detail(detail_data)
   order.tracking_number = tracking_number
   ```

3. **API эндпоинт**:
   - `mtop.taobao.order.query.detailv2`
   - Путь к трек-номеру: `data.data.logisticsPackages.fields.packageInfos[0].mailNo`
