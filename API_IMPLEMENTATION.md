## 📋 Анализ предоставленных данных

### 1. cURL команда:
```
URL: https://h5api.m.taobao.com/h5/mtop.taobao.order.queryboughtlistv2/1.0/
Метод: GET
API: mtop.taobao.order.queryboughtlistV2
```

**Ключевые параметры:**
- `appKey`: `12574478` - идентификатор приложения
- `t`: timestamp в миллисекундах
- `sign`: MD5 хеш для подписи запроса
- `data`: JSON параметры запроса (queryType, page, pageSize)

**Важные cookies:**
- `_m_h5_tk` - используется для генерации подписи
- `_tb_token_` - токен авторизации
- `cookie2`, `t`, `unb` - сессионные cookies

### 2. Структура JSON ответа:

API возвращает сложную вложенную структуру, где каждый заказ представлен несколькими объектами с уникальными ключами:


## 🔧 Реализованные изменения

### 1. `backend/scraper/parser.py`

#### Метод `parse_orders_list()`
Теперь правильно обрабатывает вложенную структуру Taobao API:
- Извлекает все order_id из объектов с тегом `shopInfo`
- Для каждого order_id вызывает парсинг отдельного заказа

#### Метод `parse_order_from_json()`
Полностью переписан для работы с реальной структурой:
- Принимает `api_data` (полный data.data объект) и `order_id`
- Извлекает данные из разных объектов:
  - `shopInfo_{order_id}` - информация о заказе и магазине
  - `orderItemInfo_{order_id}_*` - информация о товарах
  - `orderPayment_{order_id}` - платежная информация
  - `orderDeliverTime_{order_id}` - статус доставки
- Собирает все данные в единую структуру заказа

#### Метод `_normalize_status_from_titles()`
Новый метод для определения статуса на основе китайских названий:
- **"买家已付款"** → `paid` (Покупатель оплатил)
- **"待发货"** → `paid` (Ожидает отправки)
- **"待收货"** → `shipped` (Ожидает получения)
- **"已完成"** → `delivered` (Завершен)
- **"交易关闭"** → `cancelled` (Закрыт)

### 2. `backend/scraper/taobao_client.py`

#### Обновленный метод `get_orders()`
Теперь делает настоящие HTTP запросы к Taobao API:

1. **Генерация timestamp**: текущее время в миллисекундах
2. **Извлечение cookies** из браузера через `_get_cookies_dict()`
3. **Генерация подписи (sign)**:
   ```python
   sign_string = f"{token}&{timestamp}&12574478&{data_param}"
   sign = hashlib.md5(sign_string.encode()).hexdigest()
   ```
4. **Формирование параметров запроса**: все необходимые query параметры
5. **HTTP запрос** через `httpx` с cookies и headers
6. **Парсинг ответа** через `TaobaoParser.parse_orders_list()`

#### Новый метод `_get_cookies_dict()`
Извлекает cookies из Playwright браузера в формат словаря для HTTP запросов.

### 3. `backend/scheduler.py`

#### Метод `sync_orders()`
Раскомментирован и адаптирован:
- Использует обновленный `TaobaoClient`
- Получает уже распарсенные заказы
- Сохраняет или обновляет заказы в базе данных
- Логирует статистику (новые/обновленные заказы)

## 🚀 Как использовать

### 1. Убедись, что все зависимости установлены:
```bash
source venv/bin/activate
pip install -r requirements.txt
playwright install chromium
```

### 2. Запуск сервера:
```bash
./start.sh
```

### 3. Первая синхронизация:

При первом запуске:
1. Откроется браузер Playwright
2. Авторизуйся вручную на Taobao
3. Cookies будут сохранены в `taobao_cookies.json`
4. Система автоматически начнет синхронизацию заказов

### 4. Автоматическая синхронизация:

После первой авторизации:
- Планировщик будет автоматически запрашивать заказы каждые N часов (настраивается в `.env`)
- Заказы будут обновляться в базе данных
- Статусы будут отслеживаться

## ⚠️ Важные замечания

### 1. Tracking Number (Номер отслеживания)
В текущей реализации tracking_number остается `None`, потому что в предоставленном JSON примере его не было видно. Он появляется только после того, как продавец отправит товар.

**Где искать tracking_number:**
- Возможно в объекте `orderExt_{order_id}`
- Или появляется отдельный объект `logistics_{order_id}`
- Требуется проанализировать ответ API для заказа, который уже отправлен

### 2. Подпись (Sign) и безопасность
API Taobao требует подпись запроса (MD5 hash). Текущая реализация:
```python
sign = md5(f"{token}&{timestamp}&{appKey}&{data}")
```

Где:
- `token` - первая часть cookie `_m_h5_tk` (до символа `_`)
- `timestamp` - текущее время в миллисекундах
- `appKey` - константа `12574478`
- `data` - JSON строка с параметрами

### 3. Cookies и авторизация
Cookies имеют срок действия. Если получаешь ошибки:
1. Удали `taobao_cookies.json`
2. Перезапусти приложение
3. Авторизуйся заново

### 4. Пагинация
API поддерживает пагинацию:
- `page` - номер страницы (начиная с 1)
- `pageSize` - количество заказов на странице (рекомендуется 15-20)

Для получения всех заказов можно реализовать цикл по страницам.

## 🐛 Возможные проблемы и решения

### Проблема: "API вернул ошибку"
**Решение:**
1. Проверь, что cookies актуальны
2. Проверь подпись (sign) - она должна пересчитываться для каждого запроса
3. Проверь, что timestamp корректный

### Проблема: "Не удалось распарсить заказ"
**Решение:**
1. Сохрани raw_data в логи
2. Проверь структуру JSON - Taobao может менять структуру
3. Обнови маппинг полей в `parse_order_from_json()`

### Проблема: "Неизвестный статус"
**Решение:**
1. Посмотри логи - там будет показан нераспознанный статус
2. Добавь его в `_normalize_status_from_titles()` или `_normalize_status()`
